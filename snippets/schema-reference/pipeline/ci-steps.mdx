  Each copy reads its values with &lt;&lt; matrix.&lt;axis&gt; &gt;&gt; in any templatable
  field, including infrastructure. Each copy runs as a step of its own,
  with an id made of the step id and its axis values in axis-name order
  (test-pg15-20) and a name with its values in parentheses. A copy's id
  can't be the id of another step or of another matrix's copy. Step
  concurrency limits copies across runs: without a key each copy has its
  own slot, and an explicit key is one limit for every copy. Copies of one
  run don't wait for each other's concurrency; use max_parallel for that.
  Other steps can't read a matrix step's outputs or inputs, since there is
  one per copy.

  See: [StepMatrix](/pipelines/config-reference/steps#stepmatrix)

  Omit the field to run the step on every run.

  with the commit of this step's latest successful execution in the same
  pipeline variant. If no changed file matches a pattern, the step is
  skipped with the cause `NO_WATCHED_CHANGES`. A skipped or failed
  execution never becomes the baseline, so a change stays pending until
  the step succeeds. The step always runs when it has no earlier success,

  comparison is inconclusive. Patterns support `*`, `**`, `?`, `[abc]` and
