### `ravion service-account create`

Create ServiceAccount

```bash
ravion service-account create [flags]
```

**Flags:**

| Flag | Required | Description |
| --- | --- | --- |
| `--name <string>` | yes | User-facing service account name. |
| `--description <string>` |  | Optional context for what this service account is used for. |
| `--json` |  | emit response as JSON |
| `--role <roles>` |  | Deprecated: use roles. Writing it sets `roles` to this one role; it cannot be sent with `roles`. `OWNER` is accepted as `admin`. Reads return the service account's role with the most access, or its first custom role. |
| `--roles <admin>` |  | The roles the service account holds across the organization, each a system-managed role key (admin, `member`, `viewer` or `billing`) or a custom role ID. It holds at least one, and cannot hold `owner` or a role that can delete the organization. Reads list system-managed roles from least to most access, then Billing, then custom roles by name. Setting `roles` replaces the whole set. Roles other than `admin` require policy administration to be enabled for the organization, and the caller can add or remove only roles whose permissions it already holds. |
