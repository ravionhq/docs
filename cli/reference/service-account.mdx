## `ravion service-account`

Create a service-account API key in the dashboard: Settings &gt; Service accounts &gt; select the account &gt; Create API key. Use it as RAVION_API_KEY for automation, not a personal membership key.

**Aliases:** `service-accounts`

### `ravion service-account assignable-roles`

List Assignable Service Account Roles

```bash
ravion service-account assignable-roles [flags]
```

**Flags:**

| Flag | Required | Description |
| --- | --- | --- |
| `--action <string>` |  | Create is the default. Update requires the service account being edited. Available values: create, update. |
| `--json` |  | emit response as JSON |
| `--target-id <string>` |  | Existing service account ID; valid only for update. |
| `-v, --verbose` |  | show full output |

### `ravion service-account create`

Create ServiceAccount

```bash
ravion service-account create [flags]
```

**Flags:**

| Flag | Required | Description |
| --- | --- | --- |
| `--name <string>` | yes | User-facing service account name. |
| `--description <string>` |  | Optional context for what this service account is used for. |
| `--json` |  | emit response as JSON |
| `--role <roles>` |  | Deprecated: use roles. Writing it sets `roles` to this one role; it cannot be sent with `roles`. `OWNER` is accepted and sets `platform-admin` and `operator`. Reads return the service account's role with the most access, or its first custom role. |
| `--roles <platform-admin>` |  | The roles the service account holds across the organization, each a system-managed role key (platform-admin, `operator`, `manager`, `read-only` or `billing`) or a custom role ID. It holds at least one, and cannot hold `owner` or a role that can delete the organization. Reads list system-managed roles in that order, then custom roles by name. Setting `roles` replaces the whole set. Roles other than `platform-admin` and `operator` require policy administration to be enabled for the organization, and the caller can add or remove only roles whose permissions it already holds. |
