## PipelineConfig

Pipeline configuration - the top-level schema

<ResponseField name="triggers" type="PipelineTrigger[]">
  Webhook triggers that automatically start pipeline runs on events like git push

  See: [PipelineTrigger](/pipelines/config-reference/triggers#pipelinetrigger)
</ResponseField>

<ResponseField name="inputs" type="PipelineInputDefinition[]">
  User-configurable inputs that can vary per run — environment name, image tag, feature flags, etc

  See: [PipelineInputDefinition](/pipelines/config-reference/inputs#pipelineinputdefinition)
</ResponseField>

<ResponseField name="variants" type="VariantDefinition[]" required>
  Deployment variants such as production, staging, or dev — each variant can lock specific input values

  See: [VariantDefinition](/pipelines/config-reference/variants#variantdefinition)

  _(minItems:1)_
</ResponseField>

<ResponseField name="steps" type="Step[]" required>
  Ordered list of steps to execute — steps run sequentially unless wrapped in a parallel block

  See: [Step](/pipelines/config-reference/steps#step)

  _(minItems:1)_
</ResponseField>

<ResponseField name="pipeline" type="PipelineConfigTarget">
  The pipeline this config is for. `ravion pipeline config pull` writes it,
  and the Ravion GitHub App reads it to find the pipeline a repository's
  ravion-pipeline.yaml configures. Applying a config whose block names
  another pipeline is refused. It is not stored on a pipeline version.

  See: [PipelineConfigTarget](/pipelines/config-reference/other-types#pipelineconfigtarget)
</ResponseField>
</Visibility>
