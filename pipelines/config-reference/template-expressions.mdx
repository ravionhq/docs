## Template expressions

Fields marked _templateable_ accept `<< expression >>` template tokens.

- Block mode preserves the resolved type:

  ```yaml
  timeout: << pipeline.input.timeout >>
  ```

- Interpolation mode always produces a string:

  ```yaml
  name: "prefix-<< pipeline.input.env >>"
  ```

Supported operators: `+`, `-`, `*`, `/`, `%`, `>`, `<`, `>=`, `<=`, `==`, `!=`, `&&`, `||`, `!`.

Ternary: `<< condition ? trueVal : falseVal >>`. Default fallback: `<< input.x || "fallback" >>`.

Access: `array[0]`, `map["key"]`, `map.key`. Functions: `len()`, `upper()`, `lower()`.

Escaping: write `\<<` to emit a literal `<<`; an escaped block is kept as text and never evaluated. A backslash that itself needs to be literal doubles (`\\<<` is a live template preceded by a backslash).

Available namespaces: `pipeline.input.*`, `pipeline.run.{id,description}`, `pipeline.variant.{id,name}`, `steps.{id}.{output,input}.*`, `step.input.*`, `environments.{env}.modules.{module}.output.*` and `projects.{project}.environments.{env}.modules.{module}.output.*` (last-applied stack outputs of a module; steps and variants only — bare `modules.*` is not allowed in pipeline configs), `trigger.payload.{branch,commit,ref,repository,event,tag}`.
