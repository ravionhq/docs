## Readme

Manages an AWS compliance baseline with GuardDuty, ECR image scanning, and regional CloudTrail audit trails.

### Account-level setup

Deploy one module for an AWS account and select every Region you want covered. The runner Region controls where Terraform executes and hosts the shared CloudTrail bucket; the Regions list controls GuardDuty, ECR scanning and CloudTrail trails. Every selected Region must already be enabled for the account.

Each selected Region receives a GuardDuty detector with explicitly managed protection plans and an ECR registry scanning rule covering all existing and future private repositories. CloudTrail trails cover all selected Regions by default, or the CloudTrail regions subset when set. Application alarms and application log retention remain in their respective modules.

### GuardDuty

S3, EKS audit logs, EC2 malware, RDS login, and Lambda network protection are enabled by default. Runtime Monitoring is opt-in because it adds security-agent costs. Each protection plan is explicitly enabled or disabled in every selected Region.

GuardDuty sends findings to EventBridge. The finding publishing frequency controls updates to existing findings, defaulting to every 15 minutes. Central aggregation and notification routing are configured separately. GuardDuty protection plans incur AWS charges.

### ECR image scanning

Basic scan-on-push is always enabled with a registry-level `*` filter. It covers repositories used by ECS, EKS, EC2, Lambda, and other workloads, including repositories created later. This declares the registry settings checked by OneLeet's image-scanning monitor.

Basic scans check operating-system vulnerabilities on new image pushes. They do not provide continuous scanning or automatically scan all images pushed before this configuration was enabled.

### CloudTrail

CloudTrail is enabled by default and creates one single-Region trail in each selected Region. CloudTrail regions optionally limits trails to a non-empty subset of Regions; leave it blank for all selected Regions. Turn CloudTrail off to disable all trails. Each trail records read and write management events with log file validation and no data events. The trails share one bucket in the runner Region.

Include us-east-1 in Regions and, when set, CloudTrail regions to capture IAM changes and other global service events (CloudFront and the STS global endpoint). Only that trail includes global service events; us-east-1 is not added automatically. STS regional-endpoint events are recorded in their respective Regions.

Logs go to a dedicated private S3 bucket with public access blocked, bucket-owner-enforced ownership, versioning, and encryption. Log retention (days) sets lifecycle expiry for current and noncurrent object versions; 365 is the default and 0 keeps them forever. With versioning, current-object expiry makes a version noncurrent, then noncurrent expiry applies.

Leave KMS key ARN blank for SSE-S3, or supply a key in the bucket's runner Region, even for trails in other Regions. Its policy must allow cloudtrail.amazonaws.com to encrypt logs for every selected trail. This module does not manage the key policy.

The first copy of management events per Region is free; S3 storage and optional KMS usage incur charges. If an existing trail already records those events in a Region, the additional copy is paid. Leave those Regions out via CloudTrail regions, or turn CloudTrail off if an organization trail already provides full coverage.

Destroy fails while the bucket contains logs or object versions: force deletion is disabled. Disabling CloudTrail also attempts to remove its bucket, so preserve or explicitly remove retained logs before doing so.

### Existing resources and ownership

GuardDuty detectors and ECR scanning configurations are shared by the whole account in each Region. Keep exactly one Terraform owner per account and Region; do not deploy overlapping instances or also manage them from a VPC or service module.

If GuardDuty is already enabled, import the existing detectors into this module's Terraform state before applying. Do not disable GuardDuty just to adopt this module. Existing protection-plan settings are reconciled to the selected inputs.

Applying replaces any existing ECR Enhanced scanning or custom filters with Basic scan-on-push for all repositories. Review the current configuration before adoption. Manually configured ECR registries can be managed by applying this module.

Removing a Region or destroying the module deletes its GuardDuty detector and findings and resets ECR scanning to Basic without registry rules. It does not delete ECR repositories or images.

### Configuration

| Setting | Default | Purpose |
| --- | --- | --- |
| AWS account | Required | Account whose regional security settings are managed. |
| Region | Required | Terraform runner Region. |
| Regions | Required | Regions covered by GuardDuty, ECR scanning and CloudTrail. Include us-east-1 for IAM changes. |
| ECR scanning | Basic scan-on-push for all repositories | Always enabled by this module. |
| CloudTrail | Enabled | One single-Region management-event trail in each selected Region, sharing a runner-Region bucket. |
| CloudTrail regions | All selected Regions | Optional subset of Regions; omit Regions already covered by an existing trail. |
| Log retention (days) | 365 | S3 lifecycle expiry; 0 keeps logs forever. |
| KMS key ARN | None (SSE-S3) | Key in the bucket's runner Region whose policy permits encryption for every trail. |
| S3, EKS, malware, RDS, Lambda protection | Enabled | GuardDuty protection plans. |
| Runtime monitoring | Disabled | Optional workload security agents. |
| Automated agent management | EKS, ECS Fargate, EC2 | Used when Runtime Monitoring is enabled. |
| Finding publishing frequency | Every 15 minutes | Export cadence for updated GuardDuty findings. |
| Tags | Standard Ravion tags | Additional tags for GuardDuty, CloudTrail and its bucket; ECR registry scanning does not support tags. |
