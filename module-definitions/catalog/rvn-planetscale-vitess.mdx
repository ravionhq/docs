## Readme

Managed PlanetScale MySQL with application credentials, safe migrations, and in-place cluster resizing.

### Overview

Creates one Vitess database with a main branch, manages its default keyspace,
and generates a read/write application credential. Each module instance owns
its database. The initial size is PS-10; safe migrations and deletion protection
are enabled. PlanetScale's built-in backups remain in effect.

### Use cases

| Scenario | Benefit |
| --- | --- |
| MySQL application | Provision the database and consume its connection outputs. |
| Growing workload | Resize the default keyspace without replacing the branch. |
| Separate Ravion environments | Give each environment its own database and lifecycle. |

### Provisioning

Uses the standard Ravion Terraform change and destroy pipelines. No separate
PlanetScale pipeline or pipeline ID is required.

The first deployment creates the branch at the selected size, its default
keyspace, and application credentials. From the second deployment, the module
automatically imports that existing keyspace into Terraform state and manages
its size and extra replicas. An import can resize it in the same apply; it
does not copy data or create another keyspace. Extra replicas are first applied
on the second deployment, even if configured initially.

### Configuration

| Setting | Behavior |
| --- | --- |
| PlanetScale integration | Required active connection from Settings → Integrations. Supplies the organization and short-lived credentials. |
| Database name | Generated from project, environment and module names. |
| Database region | Required PlanetScale region slug, such as us-east; choose a Vitess-supported region near the application. |
| Cluster size | PS-10 by default. Region availability and pricing vary. |
| Extra replicas | Zero by default; reconciled from the second deployment. Additional replicas increase cost. |
| Application credential CIDRs | Empty by default (no source-IP restriction). Enter CIDR ranges to restrict access. |
| Deletion protection | Enabled. Disable and apply before destroying; Terraform deletes the default keyspace before the branch. |
| Safe migrations | Enabled. Main-branch schema changes require PlanetScale deploy requests. |
| Terraform execution environment | Runner location; independent of database placement. Each Terraform step has a 45-minute timeout. |

### Metrics

Declares 63 native branch/tablet chart candidates using the saved integration.
Metrics work from the first successful deployment; no keyspace adoption,
CloudWatch account, exporter, or separate metrics database setting is required.
Shard, tablet, and availability-zone series remain separate. Missing or
engine-specific metrics are shown as unavailable rather than zero.

Metrics currently preserve raw native values. Unit/rate semantics and live
availability are not fully verified; metric support depends on the engine,
topology, and activity of the branch.

### Application connections

Connect with the host, port, database_name, username and sensitive password
outputs. A sensitive connection_string is also available. Configure TLS
certificate and hostname verification in your MySQL driver; clients use
different TLS options. Passwords are stored in Terraform state.

The application credential has read/write data access. Schema migration
credentials and PlanetScale deploy-request workflows are separate concerns.

### Advanced configuration

Uses the same Terraform settings as other Ravion modules: OpenTofu version
override, Ravion Terraform workspace name, and Advanced Terraform variables.
Change and destroy pipelines inherit the environment's normal pipeline defaults;
configure those defaults at organization, project, or environment scope, not as
PlanetScale-specific module inputs. Advanced Terraform variables override the
generated variables.

Advanced Terraform variables can configure additional keyspaces and passwords,
VTGate sizing/autoscaling, and custom backup policies. These options can add
charges. Custom backups are optional; built-in backups remain available
without them. Cluster sizes are listed for the selected organization and
region, including Metal SKUs with their NVMe disk capacity. Additional branches,
VSchema and deploy requests are outside this release's scope.

### Design decisions

Database identity and region are fixed after creation. Compute sizing remains
editable. The first deployment uses PlanetScale's automatically-created default
keyspace. Later deployments adopt it automatically, using the previous
deployment's branch ID; they never create a second default keyspace. On
destroy, Terraform deletes an already-imported default keyspace before
deleting the branch. Disable branch deletion protection and apply first.
This deletion order needs verification with a disposable PlanetScale database
before production use. No AWS resources are needed for the PlanetScale
database itself; AWS is used by the Terraform runner and short-lived secret
delivery. Plan, apply, and destroy each use their own temporary token from
the selected integration; no bootstrap credential reaches the runner.
